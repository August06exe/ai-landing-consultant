# 陪跑排程器（D 线的一页纸闹钟）

> 版本 1.0 / 2026-09-19（第3轮审核轮新增）｜ 收件人：老板
> 为什么有这页纸：D 线工序全是日历驱动（每周/每月/每季），但人靠记忆必漏——c6 交付当天，照本页把所有日期一次性写进你自己的日历（每条一个提醒），D 线才算真的排上了。**交付当天不做本页 = 陪跑承诺是空头支票。**

## 一、部署当天（c6 完成时）立即排入日历

| 日期 | 动作 | 对应工序 |
|---|---|---|
| 交付日起 **连续 7 天**（每天上午 5 分钟） | 看 dashboard 用量一眼（成本观察期）；**顺便瞄一眼心跳抄送来没来** | c4 步骤5 / d1 / d2 L0 |
| **Day 1**（部署次日） | 微信问客户「昨晚重启电脑了吗？心跳今天来了吗」——重启测试由**客户自己动手**（你远程教） | d1 |
| **Day 7** | 首周回访：使用率盘点+教学查漏+成本小结 | d1 |
| **每周固定一天**（建议周五下午，与客户约死） | d3 周反馈三问（顺手吗/别扭吗/想要什么）+扫一眼本周用量 | d3 |
| **每月固定一天**（建议月初第 1 个工作日） | d4 月度体检（五项清单） | d4 |
| **每季度** | 季度回访（d5 既有约定）；顺手清一次自己手头的 07-工作区 | d5 |

## 二、每日被动探测（不占日程，但要知道信号）

- **心跳双报**（c2 v2.2）：客户 agent 的心跳日报会抄送到你的微信。**某天早上没收到抄送** → 按 d2 L0 开诊：先发零成本探针（微信给 agent 发「在吗」），再按 L1/L2 走
- 这是 D 线唯一靠「没发生」触发的动作——它依赖双报配置存在，交付验收（c5）时必须确认抄送真的到过你微信至少一次

## 三、L3 陪跑期的额外节拍

| 节拍 | 动作 |
|---|---|
| 每周反馈日顺带 | 工作流微调额度记账（每月 ≤4 次，超了按超纲三档走） |
| 月度体检日 | d4 五项：自写技能/记忆/成本/心跳到达率/使用率——产出月报（价值区置顶） |

## 四、为什么信任这页纸

- D 线四道工序（d1-d4）+d5 回访，全部时间触发点已收敛到本表，无遗漏（第 3 轮审核 P1-4 的修复件）
- 排程器本身归档在客户文件夹 `03-陪跑日志.md` 头部——换人接手陪跑，先看这页
