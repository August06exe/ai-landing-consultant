## 反拉屎三原则

1. **先查路由表再建文件**。路由表没有的类型 → 先在本文件补一行，再建文件。
2. **归属暂时说不清 → 一律进 `07-工作区/`**，30 天内转正（搬去正确位置）或删除。
3. **项目根目录永远只有 README.md**。任何层级的新文件不许出现在根目录。

## 归档规则

1. **结案客户**：d5 完成后，客户夹从 `05-客户/` 整体搬入 `06-归档/已结案客户/`，夹名不变。
2. **被替代文件**：重写/废弃的文档（如旧版专题、旧版提示词）不删除，移入 `06-归档/废弃文件/`，命名 `YYYYMMDD-原名.md`。
3. **归档≠删除**：归档区只进不出，历史永远可追溯。
4. 归档动作触发点：d5 复盘时、月度复盘时顺带清一次 `07-工作区/`。

## 工作区规矩（详见 `07-工作区/_规矩.md`）

一切「我现在不知道该放哪」的输出 → `07-工作区/YYYYMMDD-主题/`。存活 ≤30 天；转正去向：知识库专题 / 客户夹 04-调研 / 废弃文件。

## 版本规则

1. 每个产出文件头部：`版本 / 日期 / 收件人（老板｜客户的人｜客户的Hermes）/ 适用客户`。
2. 改动必升版本（+0.1 小改，+1.0 重写），文件尾附一行变更记录。
3. 交付包验收后冻结：陪跑期变更走 d3，出新版工作流文件，旧版标 `[已废弃]` 不删（可回滚）。
4. 知识库文档超 3 个月未复核，引用前先看抓取日期。
