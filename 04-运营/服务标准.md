# 服务标准（v1.0，2026-09-16 定稿）

> 本文件是副业的「宪法」：所有模板、SOP、顾问行为以此为准。修订需老板拍板并升版本号。

## 1. 服务包（只报包，不接散工）

| 包 | 内容 | 边界 |
|---|---|---|
| **L1 纯部署** | Hermes Desktop 装好、第一个模型接通、网关连好、1 条示范工作流、1 页使用卡 | 不含定制工作流设计 |
| **L2 部署+工作流** | L1 + 3-5 条定制工作流（按三轮访谈定稿） | 不含陪跑 |
| **L3 全程托管** | L2 + 陪跑 1 个月（可续） | 超纲需求按 §5 处理 |

定价：老板定（另立报价单）；顾问只提供**工时与 token 成本测算**供参考。

## 2. 标准交付流程（全流程一览）

```
建档 → 三轮访谈 → 方案拍板 → 交付包制作 → 部署引导 → 自装配验证 → 验收交付 → 陪跑 → 复盘与自进化
       (c1)        (c2)        (c3)         (c4)        (c5)          (c6)       (d1-d4)   (d5)
```

## 3. 三轮访谈制（需求调研的法定形状）

- **第一轮·初访**：老板见客户（30-60分钟），用顾问出的题单了解：业务背景、每天/每周重复在干什么、设备与网络、预算与模型付费意愿、入口偏好、禁区。记录进 01-档案与需求。
- **中间轮·方案**：顾问出**初步方案 + 可能性工作流清单**（每条附一句 ROI：用几次、省多少事）。老板消化。
- **第二轮·确认**：老板带方案再见客户：确认工作流优先级、砍掉不值钱的、逐条认可验收演示场景。定稿后才开工。

原则：**方案没确认不开工**；客户说「都行」就挑最痛的一条先做。

## 4. 部署与交付范式（自装配）

- 部署目标只设一条底线：**Hermes 活了 + 第一个模型通了 + 安全基线设好**。
- 然后**把交付包甩给客户那台空白 Hermes，让它按自装配指令把自己装配成专属 agent**。
- 老板用 UU 远程操作客户电脑，**全程录屏**存 00-商务。
- 自装配失败项 → 降级为老板手动配置（回退方案见 SOP c5），事后把坑回填知识库。

## 5. 陪跑 SLA（L3）

- 期限：1 个月，可续。
- 响应：工作日客户消息**当天回、次日处理**；非紧急攒到每周固定反馈。
- 包含：**每月 ≤4 次**工作流微调（小改：改提示词/触发词/时间）。
- 超纲需求三档：**小**=顺手做（给惊喜）；**中**=记入二期清单；**大**=加钱报价。顾问先出工作量估计（小/中/大），老板对外回复。

## 6. 验收标准

- 每条工作流必须有**验收演示场景**（客户当场可复现的一个具体例子），第二轮访谈时客户认可过。
- 验收=当客户面逐条跑通 + 录屏存 00-商务 + 客户微信确认（截图存档）。

## 7. 审校分级（老板时间保护规则）

- 第一单：全部必审。
- 之后：**装进客户 Hermes 的文件必审**（自装配指令/SOUL/工作流），**内部文件抽审**（调研/陪跑计划/复盘）。

## 8. 信息与保密

- 客户信息**真名正常存储**（老板已拍板），集中在客户文件夹内。
- 顾问 agent 不接触客户、不发消息、不打听档案外信息。
- 客户素材用于宣传/案例前须客户同意。

## 9. 角色边界

| 谁 | 干什么 | 不干什么 |
|---|---|---|
| 老板 | 销售、访谈、定价、审校、部署操作、客户唯一接口 | 不写交付包、不查文档细节 |
| 顾问 agent | 调研、方案、交付包制作、故障技术支持、复盘分析 | 不接触客户、不报价、不擅自定需求 |
