# 换机迁移 Runbook（旧机 → 新机）

> 版本 1.1 / 2026-09-19 / 收件人：老板（部署者）
> 依据：d5 v2 硬要求——迁移是续费钩子，没有 runbook 的钩子是空头支票；行业教训「改坏/搬家之前没备份」是第一悔恨。
> 适用：客户换电脑/重装系统/电脑故障后重建。全程 UU 远程，约 60-90 分钟。

## 〇、开始前的三问

1. 旧机还能开机吗？（能 → 先做完整备份；不能 → 问云端/网盘有没有近 7 天备份，没有则走「重建模式」，见 §五）
2. 新机环境摸底：Windows 版本/杀软/网络可达性（对照 `02-知识库/01-专题/02`）
3. 约客户时间，**开录屏+知情同意一句话**（c4 同款）

## 一、备份（旧机，能开机才做）

- [ ] 关 Desktop → 整目录拷贝 `~/.hermes/`（含 **SOUL**/.env 密钥/data/日志；**AGENTS.md 不在这里**，见下一条）到 U 盘或客户自己的网盘
- [ ] **单独拷 AGENTS.md（及守则等工作目录级 md）**——它住在用户主目录/工作目录（llms-full.txt:13548），不在 `~/.hermes/` 里，漏拷=恢复出来的 agent 忘光口径表/确认点/禁用词表
- [ ] 拷贝业务工作目录（如 `D:\诚信记账\`、收件箱等，按该客户 AGENTS.md 的目录约定）
- [ ] 拷贝交付包原件（`05-客户/<客户>/02-交付包/` 你手里本来就有）
- [ ] **提醒客户密钥安全**：.env 里的 key 拷完即从 U 盘转存新机，U 盘别留

## 二、新机装机（对照 c4 标准流程）

- [ ] 装 Desktop → `hermes setup` 通第一个模型（模型与旧机一致，按 c2 选型；.env 直接拷则跳过配 key）
- [ ] 安全基线重设：allowed_users（只客户本人）/ 审批模式 / 禁区技能为零——**迁移=重设基线的机会，别偷懒跳过**

## 三、恢复（把「它」变回「它的它」）

- [ ] `~/.hermes/` 整目录回拷（SOUL/data/工作流全回来）
- [ ] **AGENTS.md（及守则）放回原工作目录位置**（照交付包 00-自装配指令第 2 步的落位说明）
- [ ] 启动后先验证人格：问「你是谁」→ 答案与 SOUL 一致
- [ ] **验证任务约定**：问一个只有 AGENTS.md 才有答案的口径（如问陈会计「金额记哪三列」、问老王「朋友圈文案带不带店名结尾」）→ 答不上来=AGENTS.md 没落位，回上一条重做
- [ ] 逐个恢复业务目录（收件箱/工作区/台账路径）——**路径变了要改 AGENTS.md 与工作流文件里的绝对路径**（升 +0.1 版本）

## 四、渠道与定时任务重验（最容易漏的两处）

- [ ] 渠道重新扫码登录（微信/飞书登旧机的会话不会跟过来）→ 用客户手机发一条确认
- [ ] **cron 全部手动触发一遍**（d2 更新后回归三件事同款：cron/渠道消息/skills list）——换机后的 cron 寄生在新网关上，不验=裸奔
- [ ] **心跳验证**：手动触发晨间汇报，客户收到 → 心跳回到岗
- [ ] 红线抽测 1 例（它还记得拒绝越界请求吗）

## 五、重建模式（旧机报废且无备份）

- [ ] 交付包原件重甩 → 自装配重跑（等于重做 c4-c6，30-45 分钟）
- [ ] 人格/工作流从交付包重建；**客户数据（台账/持仓/名单）无备份则如实告知无法恢复**——这是教训，不是耻辱：记进 03-陪跑日志，并把「每月 1 号备份提醒」检查是否真的在跑（d4 体检项）

## 六、收尾

- [ ] 三行进 03-陪跑日志：症状（换机）/根因（—）/解法（本 runbook 第 X 路径）
- [ ] 若发现了本 runbook 没覆盖的坑 → 当天回填本文件（升版本）
- [ ] 客户确认一句「和以前一样了」→ 关单
