# 心跳工作流配方（每套方案的标准配件）

> 版本 1.0 / 2026-09-16 / 收件人：顾问与客户的Hermes
> 依据：SOP v2（c2 心跳硬规则、c5 核对首项、d2 L0 失联巡逻）+ 专题08（「静默失败 7 天」教训——心跳把发现空窗从月度压到 24 小时）。

## 它同时是三样东西

1. **存在感装置**：客户每天见到它 → 「还在为我干活」的感知（价值可见）
2. **失联传感器**：它没来=整套系统出事的最早信号（兜底的兜底——业务工作流的告警会跟业务一起死，心跳独立在岗）
3. **价值展示位**：日报里带「本周已帮你完成 N 件」→ 喂给 d4 月报（模板落六要素时，在输出末尾加 📌 行：`📌 本周已帮你完成 N 件`，N=本周工作流实际成功执行次数，由 agent 从日志统计）

## 标准骨架（抄了改三处：时间/汇总内容/自检项）

```
# wf-每日晨间汇报（心跳）

## 触发
- cron：0 8 * * *（每天，全年无休——心跳不放假；店休/休息日照发「报平安」短版）

## 输出模板
📋 {助理名}晨间汇报（M/D 周X）
✅ 昨日：{各工作流一句话汇总——处理 N 件/待人工 N 条/命中 N 次；无新事件写「昨夜无新增」}
📅 今日：{今日计划——将自动做什么/等客户做什么}
📌 {周期性提醒：周日补录/每月1日拍台账/费用余量}
💓 自检：{收件目录 ✅ / 模型 ✅ / 磁盘 ✅ / 本月 token N/硬顶}
⚠️ 哪天这条消息没来，就是我没起来——请联系服务商

## 兜底
- 发送失败：重试 1-2 次 → 仍失败走第二通道（邮件/短信/家人微信）——心跳是最后一个不许静默的环节
- 日志缺失：如实写「昨日记录缺失」，不编数
- 失联判定：连续 24h 客户没收到任何消息（含心跳）→ 按 03-SOP/d2 L0 主动开诊
```

## 三处要按客户改的

1. **时间**：跟客户作息（8:00 通用；开店早的可 7:00）
2. **昨日汇总**：从各工作流的运行日志取数——所以心跳虽是第一条建的工作流，内容依赖其他工作流的日志格式（空跑期写「系统自检中」）
3. **自检项**：按该客户方案的关键依赖（收件目录/模型连通/磁盘/用量/本地模型在线…）

## 施工与验收要点

- 自装配指令里**心跳排施工第一位**（先学会报平安，再学干活）
- c5 核对表首项：手动触发 → 客户渠道 1 分钟内收到
- 心跳自身连败按 cron 失败动作升级；「今天没收到心跳」写进使用卡报障第一行
- d1 Day1 第一件事：确认当天心跳已到
