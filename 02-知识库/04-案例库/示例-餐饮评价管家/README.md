# 示例：满满轻食·餐饮评价管家（虚构完整案例）

> ⚠️ 人物与数据全部虚构。这是「服务=普通级、但情绪成本高」的客户按 c1-c6 走完一遍的样子——两个看点：**人工喂数据的诚实设计**（不教唆爬登录态页面）与**情绪分级草稿**（agent 只拟不发的转人工纪律）。

**客户**：林小满（店主，2 名兼职员工）。美团+饿了么双平台外卖，月单量约 1800，好评率 94% 但差评回复率只有六成——「差评看着来气，回了两条被气到睡不着，后来干脆不看了」；两条差评没回被顾客追着骂到私聊。
**服务包**：L2 部署+工作流（3 条工作流，无陪跑，与 04-运营/服务标准.md §1 口径一致）。渠道=微信私聊（提醒发给林小满本人）；模型=GLM（国内直连）。
**三条工作流**：每日评价简报（心跳）/ 差评告警与草拟 / 周回复复盘。

**与拉面店案例的两处不同**：
1. 评价数据是**林小满每天花 2 分钟截图喂进来**的——外卖平台评价在登录态后面，没有任何合法的免费自动抓取路径；本案例诚实从「本来就要打开后台」这一步接手，解决的是「回复耗时+情绪化+漏回」，不是幻想中的全自动爬取（冷启动纪律）
2. 差评回复是**草稿制**：agent 分级拟稿，林小满过目才发；退款/投诉/人身威胁类一律转人工，agent 不碰（转人工纪律）
