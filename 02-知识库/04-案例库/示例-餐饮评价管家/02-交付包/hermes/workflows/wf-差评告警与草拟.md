# wf-差评告警与草拟 ｜ 满满轻食版（示例）

> 版本 1.0 / 2026-09-20 / 收件人：客户的Hermes

## 1. 触发方式

- 定时：`30 11,18 * * *`（每日 11:30/18:30 两批，覆盖午晚高峰后评价高峰；执行体：cron 调起）
- 数据前置：同简报（投喂文件夹，只扫比上一批更新的条目；执行体：agent 维护 `已处理清单.txt` 记录已出过草稿的评价指纹——昵称+日期+首句前 10 字）
- 口令：「扫差评」（手动补扫）

## 2. 输入 → 输出（例子）

- 输入：投喂文件夹新增条目
- 输出（🟡🟢 级，微信私聊单发）：
  > 🟡 差评草稿（请过目）｜王** ｜ ⭐⭐⭐ ｜「少了餐！差评！」
  > 草稿：「王女士您好！抱歉让您少收了餐。当天漏发是我们的责任，您说一声我们当天重做补送或全额退。已加作出餐双核对。满小满敬上」
  > （回「1」=记为已发；回改稿意见=我改）
- 输出（🔴 级）：
  > 🔴 这条你来（王** ｜ ⭐⭐ ｜ 原文如下，我不拟稿）：「吃出头发了，要不赔要不曝光」
  > （执行体：agent 只转发原文+这一句话；不分析、不评论）

## 3. 分步 SOP

1. 扫投喂文件夹新增条目，与 `已处理清单.txt` 比对去重（执行体：read_file + agent 比对）
2. 逐条按情绪分级表判级（执行体：agent；🔴 特征——食安词/赔偿词/威胁词/模板化措辞——命中任一即 🔴，**判重从严**）
3. 🟢🟡 → 按 AGENTS 口径拟稿（执行体：agent 生成，遵守 ≤80 字/三段式/脱敏）
4. 🔴 → 只转发（执行体：gateway 推送原文）
5. 每条草稿后附「回 1 已发/回意见改」——林小满的回复是关闭该条的唯一方式（执行体：agent 监听微信回复更新已处理清单）

## 4. 失败兜底

- 本批扫完 0 新增 → 零消息（不刷存在感）
- 判级拿不准 → 按 🔴 处理（从严），附一句「拿不准，你判断」
- 林小满 2 小时未回 🟡 草稿 → 不催（她可能在忙）；18:30 批次的 🟡 顺延到次日 9:30 简报里再带一次

## 5. 验收演示场景

投喂含 1🟢+1🟡+1🔴 的截图 → 扫描后：🟢🟡 各收 1 条草稿（带脱敏/口径库引用）、🔴 只收原文转发、无重复草稿——四项全中即过。
