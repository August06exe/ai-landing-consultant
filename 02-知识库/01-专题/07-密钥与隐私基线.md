# 专题07：密钥与隐私基线（给客户配 agent 的安全底线）

> 2026-09-16 成文。背景：本项目的交付对象千差万别——从拉面店老板到持有加密资产的交易者。**安全基线必须按客户敏感度分级**，本文是 c2 方案设计和 c4 部署时的强制检查单。

## 一、密钥分四类，各有各的规矩

| 类别 | 例子 | 存放地 | 铁律 |
|---|---|---|---|
| 模型 API key | DeepSeek/OpenRouter/Anthropic key | 客户机器 `~/.hermes/.env` | 部署时现场配置；**永不进交付包、git、聊天记录、截图** |
| 渠道凭据 | 微信 iLink token、TG bot token、飞书 app 凭据 | `~/.hermes/` 各渠道目录（setup 自动存） | 扫码类凭据会过期；**谁的手机扫码=谁持有**，交付时说清 |
| 第三方工具 key | Firecrawl、TTS、Browser Use 等 | Portal 一站式（首选）或各自 .env | 小白客户一律推 Nous Portal，别让他配四把钥匙（专题02） |
| 客户业务 key | 交易所只读 key、企业微信 secret、CRM token | 客户本地 .env，**最小权限** | 只读优先；**禁提币/禁下单**类权限永远关闭；用途过期立即作废 |

**通用红线**：任何密钥不进对话（让客户把 key 粘贴给 agent 看=违规）、不进文档、不进 `git`（pre-commit 门卫 + check-privacy.sh 会拦）、不进截图和录屏。

## 二、客户敏感度分级（c1 初访就要判断）

| 级别 | 典型客户 | 基线要求 |
|---|---|---|
| **L-普通** | 餐饮/零售/个人效率 | 标准基线：官方 Desktop + 国内模型 + 微信渠道 + 使用卡三纪律 |
| **L-敏感** | 律师/财务/医疗/涉密行业 | + 本地模型或私有化 API 优先；数据不出机；交付包禁用外部网页摘要类工具；明确告知训练数据政策（`-contributor` 模型禁用，llms-full.txt:6559/:6564） |
| **L-高危** | 资产交易/密钥持有者 | + **全自托管链路**（通知走自建 Bark→APNs E2E、远程访问走 CF Tunnel+Access 双层门、禁用国内社交网关）；资产类 API 只读+禁提币；**交易执行类需求=刹车并上报老板**；私钥/助记词永不接触 agent |

> L-高危的参考架构已实战验证过一次（自托管三层：Bark + hermes dashboard + CF Tunnel），细节沉淀在对应客户档案，勿写进公开仓库。

## 三、c2/c4 强制检查单（安全基线）

- [ ] allowed_users = 仅客户本人（`WEIXIN_DM_POLICY` / 各渠道等价物）
- [ ] 审批模式：小白客户=命令需审批（approval_mode），技术客户可放宽并告知风险
- [ ] 支付/安全攻击类技能零安装（专题05 纪律）
- [ ] 模型数据训练政策：非交互任务默认拒绝 `-contributor` 模型；给客户开豁免必须口头+文字双告知
- [ ] 密钥全部现场配置进 `.env`，交付包与聊天中零密钥残留
- [ ] dashboard/远程访问若开放：必须绑自定义域名 + 反代 + 双层认证（裸奔的 `/api/pty`=公网终端）
- [ ] 高危客户：浏览器工具、网页抓取默认关；清单经老板审校

## 四、交接与退出（d5 复盘时执行）

1. 服务终止 → 客户侧密钥清单交客户本人：哪些作废、哪些保留、怎么轮换
2. 我方不留存：聊天记录归档进 `00-商务`（gitignore 区）、代码与密钥零留存
3. 客户要求删除档案 → 05-客户夹整体加密归档或删除（真名政策下客户有权要求）
