# 专题03：模型与 Provider 选型（含成本优化）

> 基于 `02-知识库/02-官方文档/llms-full.txt`（锚点实测 2026-09-19）（2026-09-15 抓取）。涉及价格的部分标注查询日期，报价前必须复核。

## 槽位模型：主模型 + 11 个辅助槽（:6457-6560）

- **主模型（main）**：agent 思考用，所有对话和工具循环都走它——成本大头。
- **辅助槽（auxiliary，11个）**：上下文压缩、视觉、网页摘要、审批打分、MCP 路由、会话起名、技能搜索等。默认 `auto`（跟主模型），**可单独指到便宜快模型**——这是给客户降成本的第一个杠杆（:6535-6557）。
- 常用override：压缩/摘要/审批用 flash 级小模型即可，「在 Opus 上烧 reasoning token 只为做总结」是典型浪费（:6549-6550）。

## Provider 四条路（:6468-6472 及 quickstart）

| 路线 | 适合客户 | 优点 | 代价/风险 |
|---|---|---|---|
| **Nous Portal**（`hermes setup --portal`） | 小白、Windows 客户（**首选**） | 一次 OAuth 搞定模型+工具类 provider（TTS/web 等多把 key 一次配齐，:87976-87978）；300+ 模型一个订阅；token 计费 9 折（:6505） | 订阅费；国内支付/网络需实测（**待回填**） |
| **OpenRouter** | 想灵活换模型的客户 | 200+ 模型一个 key | 需外币支付；网络条件 |
| **Custom API**（OpenAI 兼容端点） | **国内客户现实解**：GLM/DeepSeek/通义/中转站 | `.env` 设 `OPENAI_BASE_URL` + key 即可（:5213-5215）；人民币支付、无网络问题 | 质量参差；中转站稳定性与数据安全需尽调 |
| **本地模型**（vLLM/Ollama/LM Studio） | 数据敏感、机器好的客户 | 数据不出机 | Windows 原生支持（:87694）；质量/速度吃硬件 |

## 关键成本知识（陪跑期用）

- **会话中途切模型会重置 prompt cache**：下一条消息全量重读上下文（未缓存价），长会话一次切换可能比两模型差价还贵。默认超 100K tokens 切换要确认（:6542-6545）。→ 给客户的工作流设计里，**模型固定在一个会话内别乱切**。
- `-contributor` 后缀模型便宜但厂商可能拿数据训练；非交互任务（cron）默认拒绝用，需显式开启 `security.allow_data_training_tiers_noninteractive`——**给客户开这个前必须告知**（:6559（模型说明）/ :6564（配置键））。
- 仪表盘 Models 页有用量分析（每模型 token/成本），交付时教客户看（:6480-6484）。

## 选型决策树（顾问按客户画像套）

1. 客户能顺畅访问国外 API + 愿意外币付费？→ 体验优先：Claude/GPT 级主模型（Portal 或 OpenRouter）
2. 国内客户、要省心？→ **GLM/DeepSeek 官方 API 或可靠中转**（custom endpoint），主模型用旗舰，辅助槽指到便宜档
3. 数据敏感（律师/财务/医疗类客户）？→ 本地模型方案，硬件先过审
4. 预算极敏感？→ 便宜主模型 + 辅助槽全压到最便宜 + 工作流设计上减少上下文长度
