## 架构一句话

Gateway 是**一个后台进程**：连接所有已配置平台、托管会话、跑 cron 定时任务、投递语音。交互式配置 `hermes gateway setup`；装成系统服务自启 `hermes gateway install`（llms-full.txt:77/:466，命令参考 :46164 起）。

## 国内客户选型决策

**个人微信（Weixin adapter）**——客户最常见诉求，交付前必须讲清：
- 原理：走腾讯 **iLink Bot API**（官方名「ClawBot 插件」，2026-03 上线，接口在 ilinkai.weixin.qq.com——个人号官方 Bot 化的合法通道），长轮询，**免公网免备案**，扫码即连（:83968-83969 起；背景检索 2026-09-18）。
- ⚠️ **大坑**：扫码连上的 iLink bot 身份 ≠ 客户的个人微信号本身。**普通微信群消息基本收不到**，可靠可用的是「私聊这个 bot」。群功能个别账号类型可能开通，但交付时一律按「只有私聊」设计。**2026-09 复核：接口与政策无收紧，结论不变；另一侧「协议逆向/外挂式个人微信自动化」封号风险面不变——两条路别混。**
- 流程：`hermes gateway setup` → 选 Weixin → 手机扫码 → 凭据存 `~/.hermes/weixin/accounts/` → `.env` 配 `WEIXIN_ACCOUNT_ID` / `WEIXIN_DM_POLICY` / `WEIXIN_ALLOWED_USERS` / `WEIXIN_HOME_CHANNEL`（cron 推送的目标会话）。
- 依赖：`pip install aiohttp cryptography`（:83982/:83988）。

**选型速查**：
- 个人客户要微信 → Weixin adapter，但用前用后都提示群聊限制；「定时推送到微信」用 `WEIXIN_HOME_CHANNEL`。
- 企业客户 → 飞书（能力全）或钉钉（用户基数）；已深度用企业微信的 → WeCom。
- 技术型/有网络条件的个人 → Telegram（体验上限最高）。
- 「客户既要微信又要推送可靠」→ 混合方案：微信私聊 + Email/飞书做定时报告兜底。

## 维护要点

- 自启机制：Windows 用 schtasks、Linux systemd、macOS launchd（:88074-88075）。
- **凭据按 profile 隔离**；仪表盘显示「Saved」只代表凭据已存，**不代表网关在跑**——「配置了但没消息」第一嫌疑（:24507-24519）。
- cron 主动推送：每渠道有 home channel 概念；`deliver_extra.chat_id` 可指定投递目标（:31533/:31572）。
- **微信扫码登录会过期**：陪跑期客户报「没消息了」，先查网关进程，再查登录态（重新扫码），最后查 policy/allowed_users 拦截（:83747-83755）。

## 渠道无响应排查顺序（写进运维手册模板）

1. 网关进程活着吗（`hermes gateway` 状态）
2. 渠道凭据/登录态过期吗（微信→重新扫码）
3. 消息被 policy 拦了吗（`WEIXIN_ALLOWED_USERS` 等）
4. gateway 日志里该平台 adapter 报什么错
5. 平台侧问题（bot 被限流、账号风控）→ 升级给老板处理
