# 专题04：运维、更新与故障排查

> 基于 `02-知识库/02-官方文档/llms-full.txt`（2026-09-15 抓取）。这是陪跑期的「医生手册」。

## 更新（`hermes update`）

- 更新流程含依赖修复、配置迁移、**Desktop stage-and-swap 重建**（失败不碰旧版）、**网关自动重启**（llms-full.txt:814-815）。
- **Windows 三大守卫**：
  1. 有进程锁 hermes.exe 就拒绝更新（Desktop 开着/别的终端跑着 REPL/网关在跑）→ 先关 Desktop（:940-950）
  2. Python 解释器被占（.pyd 锁）→ `--force` 无效，只能 `--force-venv` 显式豁免（:958）
  3. 客户本地源码改动 → `--keep-stash` 停放进 git stash，不自动恢复，日志有恢复命令（:880）
- 更新前必问：客户有没有自己改过东西？Desktop 关了吗？
- 杀毒软件隔离 updater 脚本会导致「更新假失败」——看隔离报告修复，不许让客户关杀软（:834）。

## 会话与数据维护

- state.db 变大：先非破坏性 `hermes sessions optimize`（合并索引+VACUUM），确认不要旧会话才 `hermes sessions prune`（:6966）。
- 会话按来源打标（cli/telegram/weixin/wecom/cron…），排查「消息从哪来」有用（:6939-6966）。
- `-c` 是终端感知的：同一终端续自己的会话，不会串（:6986-6988）。

## 备份清单（交付时给客户定规矩）

`~/.hermes/` 下值得备份的：`config.yaml`、`.env`（**含密钥，提醒客户不要外传**）、`SOUL.md`、`AGENTS.md`（如有）、memory 目录、skills 目录、`weixin/accounts/`（微信凭据）。升级/迁移前先备份整个 `~/.hermes`。

## 排查路由表（症状 → 先看什么）

| 症状 | 第一 suspect | 去处 |
|---|---|---|
| 渠道没消息 | 网关没跑 / 登录态过期 | 专题01 排查顺序 |
| 更新失败 | Windows 守卫触发 | 本文件「更新」节 |
| 回复变笨/变慢 | 上下文压缩、模型被切、auxiliary 指错 | llms-full.txt:68878「My Agent Feels Dumber」；:68878-68700 |
| cron 没触发 | 网关死了（cron 寄生在网关进程）/ scheduler 线程僵死 | :15312 Scheduled Tasks；:55260 stale scheduler；:65357 Cron Troubleshooting |
| 中文乱码 | 老 Windows 控制台代码页 | :88015-88028 UTF-8 机制（正常已被处理，除非环境变量被改） |
