# d4-进化守护（月度体检：自写技能/记忆/成本/cron/使用率）

> 版本 2.0 ｜ 主责：顾问分析，老板执行 ｜ 频率：每月一次（L3 陪跑含 1 次；续费可含）
> 背景：Hermes 会自己写技能、攒记忆——这是它的卖点，也是失控风险点。守护=让它进化得安全。
> v2 依据：`02-知识库/01-专题/08`——agent 长期使用退化的三个行业实锤：①静默故障（月度间隔会漏，心跳+d2 L0 已把空窗压到 24h，本体检兜底复核）；②上下文/记忆漂移（静默压缩导致忘事、记错偏好）；③**价值不可见=悄悄停用**（客户感知不到价值就流失——月报必须量化价值，不只报成本）。

## 体检五项

### 1. 自写技能审查
让它列出自己新写的技能（或查 skills 目录变化），顾问逐个看：
- 干什么的、写得好不好、有没有重复造轮子
- **安全**：有没有碰禁区（支付/删除/外发数据）；**v2**：有没有违反「外部内容=敌意」（自写的技能会不会把外部消息当指令）
- 处置：好的保留并表扬（正反馈）、差的删、越界的删+进 化守则 强调

### 2. 记忆体检（长期退化重点）
抽查它记住了什么：有没有积累错误偏好（把口误当指令、记住过期信息）。
**v2 加测「漂移三问」**：让它复述①自己的定位（整理不决策？）②主人的三个最高频工作流③自己的禁区——答不对=人格/记忆已漂移，重读 SOUL.md/AGENTS.md 校正。
清理：让它自己总结「你对我主人的理解」，错了纠正，陈旧的记忆刷新。

### 3. 成本复查
Desktop 仪表盘看月 token 用量与模型分布：
- 对照 c2 硬顶：逼近 80% 就提前预警，不是超了才说（v2）
- 异常高 → 查哪条工作流烧的（长上下文/高频 cron），降频或压缩
- 辅助槽还是 auto 且主模型贵 → 指到便宜档（02-知识库/01-专题/03）

### 4. cron 与工作流健康
- 有没有客户从来不用的 cron → 建议停掉（省 token 不添乱）
- 失败过的 cron → 修或删
- **v2**：心跳工作流每日汇报的到达率抽查（本月漏了几次？漏的那几天发生了什么——这是静默故障的月度兜底复核）

### 5. 使用率与价值量化（v2 新增，月报的原料）
- 逐条工作流统计本月真实使用次数（心跳日报计数 + Day7 类盘点 + 客户确认）
- 折算价值：完成 N 件任务 × 每件省的时间 ≈ 省出 X 小时；按客户时薪/市价粗算折 Y 元——粗估即可，但要标注口径
- 从不使用的工作流 → 触发 d3 讨论（砍掉还是重设计），**价值来自使用，不来自存在**

## 产出

**月报**发到客户微信（可让 Hermes 写初稿、老板发）：
- **价值区置顶**（v2，最重要放最前）：本月完成 N 件 / 省出约 X 小时 / 折合约 Y 元
- 次要区：它学会了什么 / 花了多少钱（对照上限）/ 下月建议
- 月报同时是**续费触点**——价值可见，续费才顺（行业证据：定期报告省了多少钱能直接压流失率）

## 质量标尺（每次体检，逐条打勾才算完）

- [ ] 五项全查，无跳项；自写技能逐个有处置结论
- [ ] 漂移三问有答案记录；答偏的已校正
- [ ] 成本对照硬顶有结论（余量百分比）
- [ ] 心跳到达率有数字，漏发日有解释
- [ ] 逐条工作流使用次数有数；零使用项有处置建议
- [ ] 月报价值区置顶且口径标注清楚
