# d5-复盘与自进化（双向进化：我方变强，客户侧自治）

> 版本 2.0 ｜ 主责：顾问起草，老板拍板 ｜ 触发：陪跑期满或客户满意结案
> 用户定调：**复盘后要想办法自己进化**——复盘的产出不是存档，是两边系统的一次升级。
> v2 依据：`02-知识库/01-专题/08`——换机/迁移是已写进服务钩子却无执行文件的缺口；失败模式的「新变体」必须沉淀回题单与模板，否则同一坑会再踩。

## 结案复盘（05-复盘.md，1 页）

- 目标达成度：验收场景 vs 实际使用（客户真的在用吗？频率如何——用 d4 的使用率数据说话）
- 工时账：预估 vs 实际，差在哪（喂给下次报价）
- 利润账：工时×时薪 vs 收款（免费单记「案例成本」）
- 客户原话：好的坏的都留（宣传素材 + 需求洞察）
- **防线复盘**（v2）：本单触发了哪些 d2 故障/哪些 SOP 防线接住了/哪些没防住——没防住的进下面回填表第一行

## 进化方向一：我方系统（每个结案单必须回填）

| 复盘发现 | 回填到 |
|---|---|
| 装配失败的坑 | 知识库对应专题 + 自装配指令模板修订 |
| 访谈没问到的问题 | c1 题单加一条 |
| 好的工作流 | `02-知识库/04-案例库/`（可复用模板化） |
| SOP 不顺的环节 | 直接修订对应 SOP（升版本） |
| 定价偏差 | `04-运营/月度复盘.md` 记录，季度统一调价 |
| **新失败模式/防线缺口**（v2） | 对照 `02-知识库/01-专题/08` 失败分类定性与既有防线对照，缺的防线写进对应 SOP 质量标尺 |

## 进化方向二：客户侧（自治进化升级）

- 更新客户的**进化守则**：把这次学到的「这位主人的新习惯」写进去
- 设定下月自检重点（如：别再自己装安全类技能/每周报告一次学会的东西）
- 确认 cron 月报在跑（它是客户侧自进化的心跳）

## 迁移与长期关系

- **换机/迁移 runbook**（v2 硬要求）：结案时确认「旧机→新机迁移分步卡」已沉淀到 `02-知识库/` 或 `05-客户/_模板/`（含：备份 `~/.hermes/` → 新机装 Desktop → 恢复 → 渠道重扫码 → cron 逐个触发验证 → 心跳确认）。迁移是续费钩子，没有 runbook 的钩子是空头支票
- **季度回访**（日历提醒）——问一句用得怎样，顺便把 d4 月报发给 ta
- 续费钩子按顺序：新工作流二期清单 → 月度体检订阅 → 换机/迁移服务
- 客户同意的案例 → 整理成宣传素材（截图+一句成果），存 `04-运营/` 宣传素材夹

## 完成标志

05-复盘 归档 + 回填清单执行完（含防线复盘）+ 迁移 runbook 确认在库 + 季度回访提醒设好 → 本单关闭。

## 质量标尺（每次复盘，逐条打勾才算完）

- [ ] 目标达成度用使用率数据支撑，不凭印象
- [ ] 防线复盘有结论：哪些防线接住了、哪些没防住
- [ ] 回填表每行有去向（文件名），执行完才算完
- [ ] 迁移 runbook 已确认在库（或本单补上）
- [ ] 季度回访提醒已设
