# c3-交付包制作（自装配指令集）

> 版本 1.0 ｜ 主责：顾问 ｜ 前置：c2 定稿 + 老板审校通过
> **范式**：交付包不是文档，是**施工图**。首要读者是客户那台刚初始化、有 shell、能装技能的空白 Hermes——每个文件都是它可执行的指令。

## 产出物（结构见 `04-运营/文件架构规范.md` §客户文件夹）

### 1. `hermes/00-自装配指令.md`（入口，最重要）
写给那台空白 agent 的施工总纲：
1. 身份宣告：你是 XX 的专属助理，读完全部文件后开始施工
2. 施工顺序：SOUL.md 写入 `~/.hermes/` → AGENTS.md 落位 → 安装技能清单（`hermes skills install …`）→ 逐条建工作流（含 cron）→ 配置 home channel → 自检
3. **每步自带验证动作**（装完技能列目录确认、建完 cron 跑一次手动触发）
4. 遇到做不了的：停下来，把卡点按模板报告给主人（哪步/报错原文/已尝试）
5. 完成报告模板：装了什么/建了什么/每项验证结果/留给主人的三件事

### 2. `hermes/SOUL.md`（人格）与 `AGENTS.md`（任务约定）
按官方规范分流：人格语气进 SOUL，任务/路径/流程进 AGENTS（llms-full.txt:13851-13990）。

### 3. `hermes/workflows/wf-*.md`（工作流，六要素缺一不可）
触发方式｜输入→输出带例子｜分步 SOP（含工具与权限）｜失败兜底｜**验收演示场景**｜版本头。
写作视角：读者是执行它的 Hermes——指令要无歧义、可执行、有验证点。

### 4. `hermes/skills/`：SKILL.md 或安装清单（官方目录技能用 install 命令）
### 5. `hermes/cron.md`：任务/时间/执行内容/投递渠道
### 6. `hermes/进化守则.md`：禁区（支付/安全类不碰）｜自写技能必须报告｜周自检（本周学会了什么/卡在哪→发主人微信）
### 7. `02-使用卡.md`（唯一给人看的 1 页）：怎么喊它、怎么报障、什么别让它碰
### 8. `00-交付说明.md` + `01-部署执行单.md`（给老板）：装配清单+验收状态栏、c4 操作 checklist

## 顾问自检清单（交老板审校前）

- [ ] 每条命令已对照官方文档验证（llms-full.txt 行号），编造=红线
- [ ] 自检「每一步 Hermes 真做得到吗」（它有 shell/文件/技能安装/cron 能力）
- [ ] 全中文、小白可读（使用卡）/机器可执行（hermes/）
- [ ] 每个替老板做的假设已标注
- [ ] 版本头齐全，交付包整体版本号已定

## 红线

- 首个交付包做完，把可复用部分沉淀为 `05-客户/_模板/` 的交付包模板（下一单加速）。
- 进化守则必须随包交付——没有守则的自进化=裸奔。
