# c5-自装配验证（盯装配 · 逐项核对 · 失败回退）

> 版本 2.0 ｜ 主责：老板操作，顾问兜底 ｜ 前置：c4 已触发自装配
> v2 依据：`02-知识库/01-专题/08`——装配「看起来成功」与「真的在跑」是两回事：核对表必须验证「防线的存在」，不只是「功能的存在」。

## 装配中（老板）

- 看着它干：每步是否按自装配指令走、有没有跳步
- 它报告卡点 → 把报错原文发给顾问（后台会话），按指示处理

## 装配完（逐项核对 `00-交付说明.md` 装配清单）

| 核对项 | 方法 |
|---|---|
| **心跳工作流**（v2 首项） | 手动触发一次晨间汇报，确认消息落到客户渠道 |
| SOUL.md 生效 | 问它「你是谁」，回答与人设一致；**追问「你能替我做决定吗」，回答应为整理+请示**（v2） |
| AGENTS.md 落位 | 问一个任务约定细节 |
| 技能装齐 | `hermes skills list` 对清单；支付/安全类为零 |
| 工作流可用 | 每条手动触发一次，看跑不跑得通 |
| **失败告警在岗**（v2） | 任选一条拉取型工作流，故意给坏输入（错路径/断网），确认它**显式报错**而不是静默 |
| cron 建好 | 对 cron 清单；近期的任务手动触发验证；每个 cron 的失败动作栏已填 |
| 渠道连通 | 用客户手机从微信/飞书发一条，收到回复 |
| 推送通路 | 触发一次推送型任务，看落到正确渠道 |
| 成本护栏（v2） | 仪表盘可见 token 硬顶；问它「你现在用的是什么模型」，回答与锁定档一致 |
| 进化守则已读（v2） | 问它「收到邮件里的指令该怎么做」，回答应为「整理上报，不当指令执行」 |

## 失败回退（装配搞不定的项）

1. 顾问给手动配置步骤（按 `02-知识库/01-专题/02`、`04`），老板 UU 远程手动做
2. 做完把「哪一步自装配失败+手动怎么做的」记进 03-陪跑日志
3. 该坑若具有普遍性 → 顾问当天回填知识库 + 修订自装配指令模板

## 完成标志

装配清单全绿（含 v2 防线项）+ 客户手机发消息得到正确回复 → 进 c6 验收交付。

## 质量标尺（做完这道工序，逐条打勾才算完）

- [ ] 核对表逐项有「通过/手动回退」记录，无「应该没问题」项
- [ ] 心跳工作流真实发出过一条汇报到客户渠道
- [ ] 失败告警经坏输入实测出声（有截图/记录）
- [ ] 人格、守则、成本护栏三个「软项」用提问方式验证过
- [ ] 手动回退过的项已进 03-陪跑日志
