# 首次点火手册（First Ignition）

> 版本 1.0 ｜ 2026-09-19 ｜ 读者：第一位真实部署者（可能是作者本人，也可能是你）
> 为什么有这页：独立外评指出本仓库「外部效度为零——样机出厂前没有点火记录」。真机验证只能由第一次真实交付完成，本手册保证：**点火的人不需要作者在场，且每一步失败都有出口。**

## 点火前的三个确认（5 分钟）

- [ ] 运行环境：bash（Windows 用 Git Bash）；本手册全部命令假定你在仓库根目录

- [ ] 你已通读 `01-顾问agent/使用说明.md`（上岗三步）与 `03-SOP/c4-部署引导.md`
- [ ] 三个质量门脚本在你 clone 的目录里跑过且全绿：
  ```bash
  bash scripts/check-numbers.sh && bash scripts/check-privacy.sh && bash scripts/check-anchors.sh
  ```
- [ ] 你与客户约好了 45-60 分钟，录屏知情同意一句话已备好（c4 准备节）

## 点火路径（对应 SOP，标预计耗时）

| 阶段 | 做什么 | 预期看到 | 失败出口 | 预计 |
|---|---|---|---|---|
| 1. 建户 | `bash scripts/new-client.sh 客户名` | `05-客户/日期-客户名/` 六件套生成 | 手动按 `04-运营/文件架构规范.md` §内层建 | 1 min |
| 2. 访谈 | 按 `04-运营/启动指令.md` 场景 A 唤醒顾问 agent（粘贴指令即可），由它按 c1 初访题单聊 | 档案 §1-5 有料（含敏感度初判） | 客户说不清 → 聚焦「每天重复什么」一问 | 30-60 min |
| 3. 方案 | 顾问 agent 跑 c2 | 三选型+工作流清单+成本护栏四件 | 分叉拿不准 → 1-3-1 问老板 | 30 min |
| 4. 交付包 | 顾问 agent 跑 c3 | 九件套齐，`check-package.sh` 绿 | 有红项 → 红项描述就是修法 | 60-90 min |
| 5. 部署 | c4 执行单逐步勾（甩包路径参考各案例交付说明，如 `D:\王记拉面\交付包\`） | 第一个模型回应截图 | 10 分钟无解改期（别硬耗） | 45-60 min |
| 6. 自装配 | 甩包+看装配完成报告 | 完成报告全绿+三件事 | 卡点报告 → 按 d2 分诊 | 10-20 min |
| 7. 验收 | c5 核对表+c6 当面验收 | 客户渠道真实收到消息 | 坏输入测试按 c5 操作卡 | 30 min |
| 8. **点火日志** | 填 `点火日志` 模板（见下） | — | — | 15 min |

## 点火后：把结果还给我们

第 8 步的点火日志是本仓库从「样机」变成「已验证系统」的唯一路径。填完：

1. 脱敏（真名→化名、截图打码）后开 [案例投稿 Issue](https://github.com/August06exe/ai-landing-consultant/issues/new?template=%E6%A1%88%E4%BE%8B%E6%8A%95%E7%A8%B7.md)，或直接 PR 到案例库
2. 实测中发现的知识库错误 → 直接改对应专题+升版本（引用纪律同 CONTRIBUTING）
3. 你踩的坑若具有普遍性 → d2 纪律：当天回填

## 已知边界（点火者应预期的诚实清单）

- 本仓库**从未被第三方完整跑通**——你遇到的第一批坑就是首批真实数据
- 自装配在多步操作上有行业级失败率（专题08 引 64% 数据），c5 人工兜底是设计的一部分，不是意外
- Windows 安装/模型接入的国内网络问题已在专题02/03/11 给出官方机制，但「实测」两个字等你来写
