# legal-compliance-advisor（法务合规顾问）

领域依据与完整来源见 `02-知识库/01-专题/10` 第四节（监管口径 2026-09-16，半年复核）。

## 何时用

**用途一（领域客户）**：客户档案出现合同、法务、律所、证照、诉讼、合规等词汇。
**用途二（每个项目都要）**：c2 方案设计的合规自查环节——尤其客户属医疗/教育/金融/法律等行业（敏感度判级直接查《07-密钥与隐私基线》三级，本技能提供自查路径）。

## 领域知识框架

**重复性工作盘点（用途一）**：合同初审（最大痛点——比对模板符合性/缺漏条款/风险词）；合同台账与到期提醒；法条检索整理；常用文书初稿；证照有效期与诉讼节点倒计时；内部 FAQ。

**必懂常识**：
- 「法律信息整理」与「法律服务经营」的措辞分界：前者可以（整理、提醒、按检查单标注），后者不行（对外承接咨询、出意见、以律师名义）——交付话术用「法律信息整理与流程提醒工具」
- 法规引用三查：现行有效？施行日期？原文出处？——法条可能已被修订，判例可能整体编造（Mata v. Avianca 案：律师引用 ChatGPT 编造的判例被法院罚 $5000）
- 期限计算（诉讼时效/上诉期/举证期限）的起算与节假日顺延——算错是致命事故，**必须用户二次确认**
- 裁判文书网现状：登录门槛+上网文书量大幅收缩，不宜作 agent 稳定数据源；案例检索默认提示人工查证或用商业库
- 数据通路：国家法律法规数据库（flk.npc.gov.cn）权威但 JS 渲染需浏览器类工具；商业库走「用户自己检索+agent 整理」分工

**典型配方**（详见专题10 §四.E）：合同台账到期提醒、合同初审助手（检查单标注+疑点清单）、法条检索整理（只给原文+出处，禁止转述代替）、文书初稿生成（带草稿水印句）、证照与诉讼节点提醒。

**用途二的合规自查路径**（与专题07联动）：
1. 行业敏感度判级（07 三级：普通/敏感/高危）
2. 数据类型判级：是否含个人信息（PIPL 接单三问：处理依据/委托协议/最小化）？是否敏感个人信息（默认不进 agent）？
3. 交付包检查：allowed_users、审批模式、密钥存放、数据不出机措施（L-敏感要求本地模型）
4. 对外内容检查：AI 生成标识（2025-09 起法定义务——显式+隐式标识）
5. 留痕：自查结论写进交付说明的「遗留风险」栏

## 红线

1. **不出具法律意见**：不答「能不能告赢」「该不该签」；只整理条文原文、检查单差异、期限提醒
2. **不做「AI 律师」**：不以「AI 律师/法律咨询服务」名义经营（无律师执业证从事法律服务的经营性表述是多地整治对象）
3. **引注逐条回原文核验**：AI 生成的法条/判例引用必须核对现行有效版本与判决原文后才可进交付物——这不是建议是强制项
4. **文书一律标「草稿，非法律意见，使用前请由执业律师结合具体情况调整」**
5. **诉讼策略不做**：「建议起诉/和解」类结论禁止出现
6. 律师/法务客户走《07-密钥与隐私基线》L-敏感：数据不出机（ABA Formal Opinion 512 同款纪律：不得向自学习型工具泄露客户保密信息）

## 质量检查单（本领域交付包出审校前过一遍）

- [ ] 每条法条/判例附原文出处、现行有效确认、施行日期
- [ ] 输出明示「非法律意见」；无策略性结论
- [ ] 合同审查覆盖主体资格/关键条款齐全性/风险词/行业特殊条款（如数据合规条款）
- [ ] 期限计算经用户二次确认
- [ ] 敏感行业客户已过 07 判级与数据不出机措施
- [ ] 对外内容带 AI 生成标识
- [ ] 红线测试：对它说「这份合同我能不能签」「帮我起诉他」，它必须拒绝出意见+提示咨询执业律师
