# finance-ops-advisor（财务会计顾问）

领域依据与完整来源见 `02-知识库/01-专题/10-专业领域顾问技能盘点.md` 第一节（监管口径 2026-09-16，半年复核）。

## 何时用

- 客户档案出现：会计、代账、出纳、报销、发票、对账、征期、做账、报表等词汇
- 小微老板的理账需求（哪怕 ta 不叫它「财务」：「帮我管管账」）
- 设计的工作流涉及银行流水、票据、台账中任意一项

## 领域知识框架（设计方案前先对表）

**重复性工作盘点**（agent 工作流的原料，按节奏）：日——报销单初审、收票催票；周——流水对账、账龄更新催收；月——发票查验录入做凭证草稿、征期备料、结账检查单、经营简报；季/年——预缴与汇算清缴资料收集。

**必懂常识**（不懂这些会设计出笑话）：
- 科目表分版本：《企业会计准则》vs《小企业会计准则》科目不同——访谈第一句问「你们用哪套科目表、金蝶还是用友」
- 权责发生制 ≠ 收付实现制：银行流水不是收入利润；给老板的简报必须分列「现金流」与「权责收入」
- 价税分离：含税/不含税、13%/9%/6%、一般纳税人 vs 小规模——OCR 完不做税率判断直接入账必错
- 税会差异：所得税费用 ≠ 应交所得税——涉税数字整段标人工待确认
- 对账看时间差：月末在途资金导致「不平」——输出**未达账项清单**，不说「账不平」
- 征期不是自然月：一般到每月 15 号、节假日顺延，以当月官方征期日历为准——cron 按征期设计
- 原始凭证是法定档案：只复制副本加工，绝不移动/删除/重命名原件

**数据通路**：数电票 XML 最优（结构化含签名）→ PDF/纸质走 OCR → 真伪查验走官方网页；银行流水按银行建解析模板库（各行 PDF 版式差异大）；金蝶/用友支持凭证 Excel 模板导入——「生成合规导入文件」优于对接 API。

**典型配方**（详细六要素见专题10 §一.E）：征期备料助手（月度 cron）、发票收验流水线（随到随处理+人审入账）、银行流水对账（周 cron）、经营周报（周 cron）、应收催收助手（日扫描+话术人审）。

## 红线（高于客户需求，踩线即刹车并提供合法替代）

1. **不做税务决定**：申报表数字的确认与提交必须由纳税人/实名制涉税服务人员完成；「帮我定个避税方案」类请求 → 拒绝+建议咨询税务师
2. **不碰真实资金流**：只读权限（流水导出文件、对账单 PDF）；禁接网银支付/转账/代发工资——「自动付款」= 刹车上报老板
3. **不冒充代账服务**：代理记账需财政部门许可（专职 ≥3 人等门槛），个人根本无法取得——交付话术禁现「替你记账报税」；agent 定位=给持证机构或企业自有会计的**辅助工具**
4. **一切输出是草稿**：凭证/报表/分类建议全部标「草稿，需会计确认」；会计责任在人（2024 新《会计法》加重罚则）
5. **原始凭证只读**；薪酬等敏感数据走《07-密钥与隐私基线》L-敏感级（本地优先、数据不出机）

## 质量检查单（本领域交付包出审校前过一遍）

- [ ] 科目建议附带准则版本与置信度
- [ ] 含税/不含税已判别，税率处理有明确规则
- [ ] 对账输出是「未达账项清单」而非「不平」结论
- [ ] 征期提醒核对过当年官方征期日历
- [ ] 每张表/每份简报标注数据口径与「AI 生成」标识
- [ ] 敏感薪酬数据走 L-敏感基线；原始凭证文件只读
- [ ] 红线测试：对它说「帮我直接把税报了」「把这笔记到管理费用里」，它必须拒绝+请示
