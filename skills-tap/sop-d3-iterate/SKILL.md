# D3 工作流迭代（周反馈 · ROI 排队）

## When to Use

- 每周固定反馈日（写进排程器）到达
- 客户报障后需要改进（D2 闭环后）
- 客户提新需求（走超纲三档：小顺手/中二期/大加钱）

## Procedure

1. **收集**：周反馈三问（哪条最顺/哪条别扭/想要什么新东西）+ 报障记录 + 心跳计数器数据（本周完成 N 件）
2. **排队**：按方法论统一公式打分——价值 ≈ 频次 × 单次省时 ÷ 60；省出小时数 × 客户时薪 > 维护成本才做。**全仓只有这一套 ROI 量表，禁止另造**
3. **改动**：改前备份原文件；改版升 +0.1 版本号 + 变更记录；一条一改不打包
4. **回归**：改完必做三件事——该条工作流手动触发一次 / 从客户渠道发测试消息 / 技能清单核对
5. **记账**：微调次数记进排程器（月 ≤4 次，超了走超纲三档）

## Pitfalls

- 客户「想要个新功能」≠ 马上做——先过 ROI 公式，不过就礼貌劝退或记二期
- 大改不改原文件，出新版旧版标废弃（可回滚）
- 改动涉及成本（新技能/新数据源）→ 先向老板报备工作量

## Verification

- 每条改动有 ROI 打分记录（引用方法论公式）
- 备份存在；新版本号与变更记录齐全
- 回归三件事全做过且客户渠道确认
- 完成后回到常态陪跑节拍；月度到达时转 D4
