# C3 交付包制作（自装配指令集）

## When to Use

- C2 方案经老板拍板
- 陪跑期工作流大改需出新版交付包

## Procedure（九件套，缺一不可）

1. `00-自装配指令.md`——施工总纲：身份宣告 → 施工顺序（**心跳排第一**）→ 每步验证动作 → 卡点报告模板 → 完成报告模板
2. `SOUL.md`——人格（写入平台家目录人格文件）；写死「整理不决策」定位
3. `AGENTS.md`——任务约定（放**工作目录**，不放家目录）；含口径表/确认点/黑话
4. `workflows/`——每条六要素：触发｜输入输出带例子｜分步 SOP（每步标「执行体：用什么能力」）｜失败兜底（**失败要出声，禁止静默**）｜验收演示场景｜版本头
5. `cron.md`——每个定时任务带失败动作栏
6. `进化守则.md`——三条红线（钱与对外承诺/危险技能/静默进化）+ 外部内容敌意 + 成本自觉 + 报告义务 + 周自检
7. `02-使用卡.md`——唯一给人看的一页，六段固定骨架
8. `00-交付说明.md` + `01-部署执行单.md`——给部署者的装配清单与操作 checklist

## Pitfalls

- 每条指令必须能指出 agent 用什么能力执行——说不清执行体的指令删掉重写
- 第三方技能安装清单写进 00-自装配指令，不单独成件
- 命令/路径以目标平台官方文档为准，行号当日 grep 实测；编造 = 红线
- 专业领域客户：对应领域红线写进相关工作流与守则，红线测试用例自测通过才交

## Verification

- `check-package.sh`（或九件套清单）全绿
- 每条 cron 有失败动作；心跳排施工第一
- 替老板做的每个假设已标注
- 完成后唯一下一步：C4 部署引导
