# C1 需求调研（三轮访谈）

## When to Use

- 客户（或老板转述）表达「想要一个 AI 助理/帮手」的任何变体
- 档案信息不完整、工作流清单未定稿、验收场景未获客户认可
- 客户说「都行/你看着办」——这是需求没挖透的信号，不是授权

## Procedure

1. **初访**（30-60 分钟，非技术话术）：按题单覆盖七问——业务背景与节奏、重复劳动清单（含纸笔/Excel 土办法，追问到能举例）、现有工具、设备网络、预算与付费意愿、时间价值、期望探底（「你希望它替你做什么决定？」）。记录进档案 §1-2 与 §5（红线与偏好）
2. **敏感度初判**：初访当场按三级（普通/敏感/高危）定级并写入档案 §5
3. **中间轮**：产出初步方案 + 可能性工作流清单，每条附一句 ROI（价值 ≈ 频次 × 单次省时 ÷ 60），按价值排序，标出建议砍掉的
4. **二访确认**：逐条确认工作流优先级与验收演示场景；方案没确认不开工

## Pitfalls

- 客户要「一个万能助手」→ 拆成单条可验收的工作流，砍到 3-5 条
- 客户期望 agent 替他做决定 → 当场校准期望（整理不决策），谈不拢就止损
- 冷启动纪律：第一条上线的工作流必须来自客户**本来就在做**的事，不是最「聪明」的场景

## Verification

- 档案 §1-5 全部回填（§5 空节 = 退回）
- 每条候选工作流有一句话 ROI + 自动化程度标注
- 验收演示场景获得客户逐条认可
- 完成后唯一下一步：进入 C2 方案设计；禁止跳到任何实施动作
