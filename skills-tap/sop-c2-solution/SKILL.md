# C2 方案设计（选型与拍板）

## When to Use

- C1 三轮访谈完成、档案定稿
- 客户改需求要求重新设计

## Procedure

1. **选模型**：按「网络条件 × 付费方式 × 数据敏感度」四选一（订阅制/聚合路由/国内直连 API/本地）；顺手定辅助槽策略（压缩/摘要/审批用便宜档）——这是降本第一杠杆
2. **选渠道**：入口跟客户现有习惯走（微信就用微信），绝不让客户学新 App；群聊限制提前说死
3. **技能配装**：技能跟工作流走，没用的不装；安全/支付类不给小白；收外部信息的工作流一律标注「草稿模式」
4. **工作流定稿**：每条按六要素搭骨架（触发/输入输出带例子/分步含执行体/失败兜底/验收场景/版本头）
5. **心跳必选 + 双报**：无论客户要什么，永远包含每日固定时点的活儿汇报；同时抄送部署者渠道（失联传感器）；末尾带「本周完成 N 件」计数器
6. **成本护栏四件**：月度费用上限数字（主口径）+ 辅助槽降档 + 守则约束（进交付包）+ 人工巡检排期
7. **安全基线**：渠道白名单（只客户本人）、审批模式、禁区清单

## Pitfalls

- 官方无「月度 token 硬顶」配置——护栏是组合拳，别承诺单一开关
- 中途切模型会清空 prompt 缓存（全量计费）——方案里写「别在长对话里反复切」
- 模型上下文 <64K 直接不可用

## Verification

- 三选型都有知识库依据，分叉走了「1 问题+3 选项+1 推荐」请示
- 每条工作流六要素齐 + 自动化程度 + 成本量级
- 心跳定义了失联判定（24h）+ 双报渠道 + 计数器
- 完成后唯一下一步：C3 交付包制作
