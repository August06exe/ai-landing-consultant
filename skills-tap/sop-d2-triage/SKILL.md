# D2 故障分诊（四级路由）

## When to Use

- 心跳双报抄送连续 24h 未到（L0 触发）
- 客户主动报障
- 更新之后（高发窗口）

## Procedure

### L0 失联巡逻（先于一切被动响应）
1. 零成本探针：部署者从自己微信给客户 agent 发一句话看回执
2. 回执有 → 通路活着，可能只是心跳 cron 挂了 → 走 L2
3. 回执无 → 微信让客户重启电脑（网关自启拉起）；再不行约远程（无人值守需部署时装好）
> 探测依赖心跳双报配置——没配双报，本级是空话

### L1 客户自检（发使用卡截图即可）
重启电脑 / 重开应用 / 渠道重新扫码 / 还不行 → 报障三要素发部署者

### L2 部署者处理（5 分钟内能做的）
- 网关没跑：启动网关命令
- 更新后回归三件事：手动触发全部定时任务 + 客户渠道发测试消息 + 技能清单核对
- 处理完让客户再发一条消息确认恢复

### L3 顾问处理
- 拉日志定位 → 给步骤让部署者执行；涉及账号风控 → 顾问给判断
- 每次处理完三行进陪跑日志：症状/根因/解法

## Pitfalls

- 「它变笨了」→ 先查：模型被切/上下文压缩/辅助槽指错，不是重装
- 恢复以「客户渠道真实收到消息」为标志，不以「我这边看着正常」为标志
- 同一问题 ≥2 次 → 升级为知识库条目 + 模板修订

## Verification

- 分诊级别判定有依据，未越级
- L0 触发的找到静默根因（不止「重启好了」）
- 三行日志已写；复发项已升级
